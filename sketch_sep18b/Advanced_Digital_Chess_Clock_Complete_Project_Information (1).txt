ADVANCED DIGITAL CHESS CLOCK WITH GAME DATA LOGGING

1. PROJECT OVERVIEW
The Advanced Digital Chess Clock is an ESP32-based electronic chess clock designed to provide accurate and configurable time control for two players. It uses two physical digital displays, physical controls, local game-data storage, and the ESP32's built-in Wi-Fi for a web dashboard. Automatic chessboard piece detection is an optional advanced subsystem.

2. OBJECTIVES
- Build a reliable two-player digital chess clock using ESP32.
- Support configurable chess time-control modes.
- Provide clear physical time displays and controls.
- Store game information locally on MicroSD.
- Provide real-time game information and analytics through a Wi-Fi web dashboard.
- Use an RTC for real-world timestamps.
- Add battery monitoring, power management, and watchdog recovery.
- Optionally detect chessboard piece movements automatically.

3. CORE FEATURES
- Two-player countdown clock.
- White and Black physical clock displays.
- Sudden Death.
- Fischer Increment.
- Bronstein Delay.
- Start, pause, resume and reset.
- Rotary-encoder based configuration.
- Buzzer and LED alerts.
- Local game-data storage.
- ESP32 Wi-Fi web dashboard.
- Game information and analytics on the web dashboard.
- Persistent settings using ESP32 NVS/internal flash.
- DS3231 timestamps.
- Battery monitoring and power management.
- ESP32 watchdog.
- Optional automatic chessboard movement detection.

5. INTERFACES
- ESP32 GPIO: buttons, rotary encoder, buzzer, LEDs and direct digital signals.
- TM1637: dedicated two-wire interface; it is NOT standard I2C.
- I2C: DS3231 and MCP23017.
- SPI: MicroSD module.
- ADC: battery-voltage monitoring through an appropriate voltage divider.
- Wi-Fi: built into ESP32 for the web dashboard.
- HTTP: web-server communication.
- WebSockets: optional for live dashboard updates.
- NVS/internal flash: persistent settings.

7. DESIGN PRINCIPLE
All move-input sources should eventually produce a common MOVE EVENT.

Button press -----------+
Reed/Hall sensor -------+----> MOVE EVENT -> Game Manager -> Clock
Future detection system-+

The automatic detection system does not need to check whether a chess move is legal. Its purpose is to detect a reliable physical board-state change and avoid false triggers from hand movement.

8. SOFTWARE / GAME STATES
Recommended high-level flow:

STARTUP -> MENU -> SETUP -> READY -> GAME -> GAME OVER -> SAVE GAME -> ANALYTICS

During GAME:
WHITE TURN <-> BLACK TURN

The countdown should use non-blocking elapsed-time calculations. Do not implement the main clock with delay(1000); time--.

9. TIME CONTROL MODES
Sudden Death:
- Fixed starting time.
- No increment.

Fischer Increment:
- Fixed starting time.
- Additional time is added after a move.
- Example: 10 minutes + 5 seconds.

Bronstein Delay:
- A delay is applied before the player's main clock decreases.

10. WEB DASHBOARD
The ESP32 can host a local web server.

Possible dashboard sections:
- Current game status.
- White and Black clock information.
- Active player.
- Selected time-control mode.
- Game progress.
- Time-pressure/status indicators.
- Game analytics.
- Saved game history.
- Game/session information.
- Device/system status.
- Configuration/settings.

The physical OLED has been removed from the design because the web dashboard handles detailed information and analytics.

11. GAME DATA LOGGING
The MicroSD card can store:
- Game/session ID.
- Date and time.
- Time-control mode.
- Starting configuration.
- Event information.
- Final result/status.
- Other useful analytics.

The DS3231 supplies real-world timestamps. The ESP32 remains responsible for the actual countdown.

12. AUTOMATIC CHESSBOARD DETECTION
This is an optional advanced subsystem.

Initial concept:
- Place a magnet in or under a chess piece.
- Place a reed switch or Hall sensor under each relevant square.
- Detect square occupancy.
- Compare the board state before and after a change.
- Wait for the board state to stabilize before generating a MOVE EVENT.

The system does not need to determine legal/illegal moves.

Development:
2x2 prototype -> larger section -> full-board architecture.

Do not purchase 64 sensors before the small prototype works.

13. POWER MANAGEMENT
Start development using USB power.

Later:
18650 battery -> TP4056 charging/protection -> appropriate regulator -> ESP32/system

Important:
- TP4056 is a charging/protection module, not a complete voltage regulator.
- Select the final regulator for the exact ESP32 board and power architecture.
- Wi-Fi can create current spikes, so the supply must be stable.
- Initially use deep sleep only for inactivity/between games, not during an active game.

14. WATCHDOG
The ESP32 built-in hardware watchdog can recover the system from software lockups.

Example:
Normal operation -> software stuck -> watchdog timeout -> ESP32 reset -> startup diagnostics -> normal operation.

External watchdog IC can be added later as a stretch feature.

19. FINAL SYSTEM
The completed device will function as a standalone digital chess clock with two clear physical player displays and physical controls. The ESP32 manages game timing and state, saves game information locally, and provides a Wi-Fi web dashboard for detailed game information and analytics.

Automatic chessboard detection remains modular and should only be included if the sensor architecture proves reliable.

PROJECT SUMMARY
The Advanced Digital Chess Clock is an ESP32-based embedded system combining digital time control, physical controls, local game-data storage, Wi-Fi connectivity and a web interface for game information and analytics. It also provides a modular path toward automatic chessboard movement detection while keeping the core clock reliable and achievable.
